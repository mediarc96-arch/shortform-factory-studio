# daehan-pilot-codex-003-A · 정적 2D 키프레임 합성

**옵션 A: 순수 정적 2D**

Grok 비디오 렌더링을 사용하지 않고, Daehan_2D.jpg 기반 정적 키프레임 5장만 사용해 30초 영상을 합성합니다.

## 구성 요소

- **베이스 이미지**: `docs/example/Daehan_2D.jpg` (1248×832, 2D 아니메 스타일)
  - 칠판 텍스트를 PIL inpaint로 제거해 깨끗한 1920×1080 플레이트 생성 → `assets/clean-board-base.png`
- **5개 키프레임**: 베이스 플레이트에서 포즈·표정만 변경 (Grok 이미지 API로 생성 또는 img2img)
- **영상 합성**: 키프레임들을 교차 페이드 + 약한 ken-burns 줌으로 연결, 상단에 손글씨 타이포 + 하단 자막 바 레이어 합성

## 장점
- Grok 비디오 API 호출 0회 → 비용·실패 리스크 최소
- 픽셀 단위 완전 제어 (두루마리 사라지지 않는 문제 없음)
- 빠른 반복 (수정 시 재렌더 1분 미만)

## 단점
- 캐릭터 입 모양·미세한 움직임 없음 → 라디오드라마 + 애니메이션 화이트보드 느낌
- 시청자가 "느리다"고 느낄 수 있어 ken-burns·타이포 애니메이션으로 템포 보완 필요

## 파일 구성

| 파일 | 용도 |
|------|------|
| `README.md` | 이 문서 |
| `pilot-spec.md` | 나레이션 스크립트·비트·타이밍 (codex-002 참조) |

| `grok-jobs/keyframe-0X-*.json` | Grok 이미지 API 호출 스펙 5개 (옵션 A는 여기까지만 Grok 사용) |

**이 옵션은 `grok-jobs/video-scene-*.json` 을 포함하지 않습니다** (비디오 API 호출 없음).

## 사용자 검수 체크포인트

1. 키프레임 5장 생성 → 사용자 리뷰
2. 각 KF 구도·포즈·캐릭터 일관성 확인 → 수정 요청 또는 승인
3. 승인 완료 후 `scripts/post/compose_final.py`로 타이포·TTS·자막 합성 (비디오 생성 없음)
